MCP configuration example

Use the real absolute path to the executable inside your installed environment. Register it at user/global scope if you want it available across projects. Client configuration formats vary; this example is for clients using mcpServers.

{
  "mcpServers": {
    "vaultic": {
      "command": "/home/YOUR-NAME/vaultic-env/bin/vaultic-mcp"
    }
  }
}

Registration makes the tools available. Automatic capture and recall also require a working host integration.

Once installed, the bundled default embedding model supports local offline operation. An external embedding API or a different downloaded model is optional. Your AI client's own connection requirements still apply.

Practical details before you buy

Privacy and backups

  • Supported content fields are encrypted by default; metadata, embeddings and keyed keyword fingerprints are not a promise of whole-database encryption.
  • The keyword index reveals patterns such as shared terms, even though it does not store readable words. Word-form and prefix matching broaden those patterns.
  • Back up all configured local stores and the separate encryption keys. We cannot recover missing keys.
  • Your client may send retrieved context to its model provider. External embedding APIs send content to the provider you choose.

Read the privacy policy →

Compatibility and limits

  • Developed and tested on Linux. Windows is planned; macOS is untested.
  • Designed for one local user. Persona/user scopes do not provide multi-tenant authorisation.
  • Recall, de-duplication and contradiction detection use heuristics. They do not guarantee complete recall or understanding.
  • Encrypted keyword search supports English word-form matching and bounded prefixes, not positional phrase search.
  • Automatic capture depends on host events and configuration. Interruptions or unavailable storage can leave gaps.
